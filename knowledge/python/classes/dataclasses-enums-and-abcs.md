# Dataclasses, enums and abstract base classes

## Summary
**TL;DR:** `@dataclass` reads a class's annotated fields and writes `__init__`, `__repr__` and `__eq__` for you, plus ordering, hashing, immutability (`frozen`) or `__slots__` on request; mutable defaults must go through `field(default_factory=...)`. An `Enum` turns names into singleton members found by value (`Color(1)`) or by name (`Color['RED']`); `IntEnum`, `StrEnum` and `Flag` add integer, string and bitwise behaviour. An ABC (abstract base class) with `@abstractmethod` refuses to create instances until a subclass implements every abstract method, and the `collections.abc` bases give subclasses ready-made mixin methods.
**Use this when:** writing a record-like class, replacing magic strings or numbers with named constants, or declaring an interface that subclasses must fill in.
**Not this doc:** how the generated special methods behave → `python/classes/data-model-special-methods.md`; plain classes and inheritance → `python/classes/classes-instances-and-inheritance.md`; structural typing with `Protocol` and `TypedDict` → `python/typing/protocols-typeddict-and-narrowing.md`; type hints → `python/typing/type-hints-and-generics.md`; the metaclasses behind `Enum` and `ABC` → `python/metaprogramming/metaclasses-and-class-creation.md`; plain tuples → `python/data-structures/lists-tuples-and-sequences.md`.

## Problem
- A hand-written record class repeats every field in `__init__`, `__repr__` and `__eq__`, and the three drift apart when a field is added.
- `tags: list = []` as a default is shared by every instance of a plain class; in a dataclass it is rejected with `ValueError`.
- Status values kept as bare strings let a typo such as `"payed"` travel through the program unnoticed.
- A subclass that forgets to implement `export()` fails only when `export()` is finally called, possibly in production.

## Mental model
**Analogy:** three kinds of templates. `@dataclass` is a form generator: you list the fields once and it prints the constructor, the display text and the comparison. An enum is a fixed roster of badges: every name has exactly one badge, and asking for badge number 2 always hands back the same physical badge. An ABC is a contract with blank clauses: the factory refuses to produce anything from it until a subclass fills in every clause.

**Artifact** (measured in the lab ✅[^lab]):
```python
@dataclass
class Item:
    name: str
    price: float
    qty: int = 0
inspect.signature(Item)                     # (name: str, price: float, qty: int = 0) -> None
Item("pen", 1.5, 3)                         # Item(name='pen', price=1.5, qty=3)
Item("pen", 1.5, 3) == Item("pen", 1.5, 3)  # True

class Color(Enum):
    RED = 1
    GREEN = 2
Color(1) is Color.RED is Color["RED"]       # True: one member, three ways to reach it

class Exporter(ABC):
    @abstractmethod
    def export(self, data): ...
Exporter()   # TypeError: Can't instantiate abstract class Exporter without an
             #   implementation for abstract method 'export'
```

## How it works
### Dataclasses
1. **Fields come from annotations.** The tutorial names dataclasses as the idiomatic way to bundle a few named data items ✅[^tut-classes]. `@dataclass` treats every class variable with a type annotation as a field, keeps them in definition order, and adds the generated methods to the class it was given rather than creating a new one ✅[^dataclasses]. It ignores the annotated type except to spot `ClassVar` (not a field) and `InitVar` (an `__init__`-only parameter) ✅[^dataclasses]. `__init__`, `__repr__` and `__eq__` are generated by default, each only if the class does not already define it ✅[^dataclasses]. The generated `__eq__` requires both objects to be of the identical type and, since 3.13, compares field by field instead of as tuples ✅[^dataclasses].
2. **Defaults.** A field without a default may not follow one with a default, in one class or across inheritance: `TypeError` ✅[^dataclasses]. `field(default_factory=list)` calls the zero-argument factory each time a default is needed ✅[^dataclasses]. A plain unhashable default such as `[]` raises `ValueError`, unhashability being used to approximate mutability (since 3.11; before, only `list`, `dict` and `set` were rejected) ✅[^dataclasses]. `field(repr=False)`, `field(compare=False)` and `field(init=False)` leave a field out of `__repr__`, the comparisons or `__init__` ✅[^dataclasses].
3. **`frozen`, hashing and `order`.** `frozen=True` adds `__setattr__` and `__delattr__` that raise `FrozenInstanceError`, a subclass of `AttributeError`; Python cannot make objects truly immutable, so this only emulates it, and the generated `__init__` must use `object.__setattr__` ✅[^dataclasses]. With `eq` and `frozen` both true a `__hash__` is generated; with `eq` true and `frozen` false, `__hash__` is set to `None` and instances are unhashable ✅[^dataclasses]. `order=True` adds `__lt__`, `__le__`, `__gt__` and `__ge__`, which compare the fields as a tuple and require the identical type; `order=True` with `eq=False` raises `ValueError` ✅[^dataclasses].
4. **`slots` and `kw_only` (both 3.10).** `slots=True` generates `__slots__` and returns a new class instead of the original ✅[^dataclasses]; its instances have no `__dict__`, so assigning an undeclared attribute fails ✅[^lab]. `kw_only=True` makes every generated `__init__` parameter keyword-only, and a pseudo-field annotated `KW_ONLY` (by convention named `_`) does the same for the fields after it ✅[^dataclasses].
5. **`__post_init__` and `InitVar`.** If the class defines `__post_init__`, the generated `__init__` calls it last, passing the `InitVar` pseudo-fields in definition order; an `InitVar` is a parameter of `__init__` and `__post_init__` only, never a field ✅[^dataclasses]. The generated `__init__` does not call a base class's `__init__`; fields of dataclass bases are initialised anyway, and a non-dataclass base can be initialised from `__post_init__` ✅[^dataclasses].
6. **Copies and conversion.** `dataclasses.replace(obj, **changes)` creates a new object of the same type by calling `__init__`, so `__post_init__` runs again ✅[^dataclasses]. `copy.replace()`, added in 3.13, does the same for named tuples, dataclasses and any class that defines `__replace__()` ✅[^copy]. `asdict()` converts a dataclass to a `dict`, recursing into dataclasses, dicts, frozendicts, lists and tuples and deep-copying every other value ✅[^dataclasses].

### Enums
7. **Members are singletons.** An enumeration is a set of symbolic names bound to unique values ✅[^enum]. The enum's metaclass creates every member while creating the class, then installs a `__new__` that only ever returns the existing members ✅[^howto-enum], and members compare by identity ✅[^howto-enum]. `Color(1)` looks a member up by value, `Color['RED']` by name, and every member has `.name` and `.value` ✅[^howto-enum].
8. **Aliases and iteration.** A second name given an existing value becomes an alias of the first member; iterating the enum skips aliases, while `__members__` lists them ✅[^howto-enum]. The `@unique` class decorator turns any alias into a `ValueError` ✅[^enum]. Since 3.12, `value in Color` checks the values too instead of raising `TypeError` for non-members ✅[^enum].
9. **`auto()` chooses values.** For `Enum` and `IntEnum` it gives the highest value seen plus one, for `Flag` the next power of two, for `StrEnum` the lower-cased member name ✅[^enum]; "highest" replaced "last seen" in 3.13 ✅[^enum].
10. **Comparisons and mixed-in types.** Plain members support no ordering, and `==` against a non-member value is always `False` ✅[^howto-enum]. `IntEnum` members are also integers and work anywhere an `int` does; arithmetic on them returns plain values ✅[^enum]. `StrEnum` (3.11) members are also strings, and string operations on them return plain strings ✅[^enum]. `Flag` members combine with `&`, `|`, `^` and `~`, and the results are members (or aliases) of the same flag ✅[^enum].

### Abstract base classes
11. **`ABC` and `@abstractmethod`.** Deriving from `abc.ABC` gives a class the `ABCMeta` metaclass ✅[^abc]. A class with that metaclass cannot be instantiated unless all its abstract methods and properties are overridden ✅[^abc]. Unlike Java's, an abstract method may have a body, which an override can call through `super()` ✅[^abc]. Combined with `classmethod`, `staticmethod` or `property`, `abstractmethod` must be the innermost decorator ✅[^abc].
12. **`register()` declares a virtual subclass.** `MyABC.register(Cls)` makes `issubclass()` and `isinstance()` accept `Cls`, but `MyABC` does not enter `Cls`'s MRO (method resolution order) and its methods are not callable on `Cls`, not even via `super()` ✅[^abc]. Abstract methods are not enforced on registered classes ✅[^abc].
13. **`collections.abc` supplies mixin methods.** Inherit from one of its ABCs and implement the abstract methods, and the mixin methods come by inheritance ✅[^collections-abc]: a `Sequence` with `__getitem__` and `__len__` gets `__contains__`, `__iter__`, `__reversed__`, `index` and `count`; a `MutableMapping` with `__getitem__`, `__setitem__`, `__delitem__`, `__iter__` and `__len__` gets `pop`, `popitem`, `clear`, `update` and `setdefault` plus the `Mapping` methods ✅[^collections-abc]. Simple interfaces such as `Iterable`, `Sized` and `Hashable` are recognised just by the presence of their methods ✅[^collections-abc]. Static structural typing with `Protocol` is in `python/typing/protocols-typeddict-and-narrowing.md`.

### Named tuples
14. **The tuple-based alternative.** `collections.namedtuple()` returns a tuple subclass whose fields are reachable by name as well as by index, with a `name=value` repr and no per-instance dictionary ✅[^collections]; `_replace()` returns a changed copy and `_asdict()` a `dict` ✅[^collections]. `typing.NamedTuple` is its typed, class-syntax version, with defaults set by assignment ✅[^typing]. Since 3.14, using `super()` in a `NamedTuple` subclass's methods raises `TypeError` ✅[^typing], and 3.15 removed the undocumented keyword form `NamedTuple("P", x=int)` ✅[^whatsnew315].

## Worked example
An order record with a status enum and an exporter interface, run in the lab ✅[^lab]:

```python
class Status(StrEnum):
    NEW = auto()
    PAID = auto()
    SHIPPED = auto()

@dataclass(frozen=True, slots=True)
class Line:
    sku: str
    qty: int
    cents: int
    def __post_init__(self):
        if self.qty <= 0:
            raise ValueError(f"qty must be positive, got {self.qty}")

@dataclass
class Order:
    id: int
    lines: list[Line] = field(default_factory=list)
    status: Status = Status.NEW
    @property
    def total(self):
        return sum(l.qty * l.cents for l in self.lines)

class Exporter(ABC):
    @abstractmethod
    def dump(self, order: Order) -> str: ...

class JsonExporter(Exporter):
    def dump(self, order):
        return json.dumps(asdict(order))

o = Order(1, [Line("pen", 3, 150), Line("pad", 1, 425)])
paid = replace(o, status=Status.PAID)
```

| # | Expression | Result |
|---|---|---|
| 1 | `o` | `Order(id=1, lines=[Line(sku='pen', qty=3, cents=150), Line(sku='pad', qty=1, cents=425)], status=<Status.NEW: 'new'>)` |
| 2 | `o.total` | `875` (3 × 150 + 1 × 425) |
| 3 | `o.status, paid.status, paid.lines is o.lines` | `new`, `paid`, `True`: `replace()` passes the same list object to the new `__init__` |
| 4 | `JsonExporter().dump(paid)` | `{"id": 1, "lines": [{"sku": "pen", "qty": 3, "cents": 150}, {"sku": "pad", "qty": 1, "cents": 425}], "status": "paid"}`: a `StrEnum` member is a `str`, so `json` writes it as text |
| 5 | `Status("paid") is Status.PAID`, `Status["SHIPPED"]` | `True`, `shipped` |
| 6 | `Order(2).lines is Order(3).lines` | `False`: `default_factory` made two lists |
| 7 | `Line("pen", 0, 150)` | `ValueError: qty must be positive, got 0`, raised by `__post_init__` |
| 8 | `o.lines[0].qty = 9` | `FrozenInstanceError: cannot assign to field 'qty'` |
| 9 | `Exporter()` | `TypeError: Can't instantiate abstract class Exporter without an implementation for abstract method 'dump'` |
| 10 | `Status("lost")` | `ValueError: 'lost' is not a valid Status` |
| 11 | `o == Order(1, [...same lines...])`, `o == paid` | `True`, `False`: field-by-field equality |

## Edge cases
| Case | What happens | Why |
|---|---|---|
| `tags: list = []` in a dataclass | `ValueError: mutable default <class 'list'> for field tags is not allowed: use default_factory` ✅[^lab] | Unhashable defaults are rejected as probably mutable ✅[^dataclasses] |
| `a: int = 1` followed by `b: int` | `TypeError: non-default argument 'b' follows default argument 'a'` ✅[^lab] | Parameters with defaults must come last ✅[^dataclasses] |
| `replace(r, area=1)` where `area` is `field(init=False)` | The docs promise `ValueError` ✅[^dataclasses]; 3.15.2 raised `TypeError: field area is declared with init=False, it cannot be specified with replace()` ✅[^lab] | `init=False` fields are not copied but recomputed in `__post_init__` ✅[^dataclasses]; catch both exception types |
| `replace(r, w=1)` on `Rect(2, 3, scale=10)` | `Rect(w=1.0, h=30.0, area=30.0)` ✅[^lab]: `__post_init__` ran again with the `InitVar` default `scale=1.0` | `replace()` goes through `__init__`; an `InitVar` without a default must be passed again ✅[^dataclasses] |
| Non-frozen dataclass in a set | `TypeError: cannot use 'Item' as a set element (unhashable type: 'Item')` ✅[^lab] | `eq=True, frozen=False` sets `__hash__` to `None` ✅[^dataclasses] |
| `F(nan) == F(nan)` with one `nan` object | `False` in 3.15.2 ✅[^lab] | Since 3.13 fields are compared one by one, which changes results for values equal by identity but not by value, such as `nan` ✅[^dataclasses] |
| `Item("pen", 1.5) == Other("pen", 1.5)`, two dataclasses with the same fields | `False` ✅[^lab] | Both instances must be of the identical type ✅[^dataclasses] |
| Setting an undeclared attribute on a `slots=True` instance | `AttributeError: 'Slotted' object has no attribute 'y' and no __dict__ for setting new attributes` ✅[^lab] | `__slots__` prevents the per-instance `__dict__`, and assigning a name not listed in it raises `AttributeError` ✅[^datamodel] |
| `Color(7)`, `Color['PINK']`, `Color.RED = 9` | `ValueError: 7 is not a valid Color`; `KeyError: 'PINK'`; `AttributeError: cannot reassign member 'RED'` ✅[^lab] | `Color[name]` raises `KeyError` for an unknown name ✅[^enum]; value lookup and member reassignment fail as shown |
| `Color.RED == 1` vs `Prio.HIGH == 3` (`IntEnum`) | `False` vs `True` ✅[^lab] | Plain members never equal raw values; `IntEnum` was designed to ✅[^howto-enum] |
| `A = auto(), B = auto(), C = 10, D = auto()` | values `[1, 2, 10, 11]` ✅[^lab] | `auto()` continues from the highest value seen ✅[^enum] |
| Code that checks `type(x) == str` given a `StrEnum` member | `type(Mode.READ) == str` is `False` ✅[^lab] | Some stdlib code checks the exact type; pass `str(member)` there ✅[^enum] |
| A class registered with `Sequence.register()` | `isinstance(obj, Sequence)` is `True`, but `obj.index` does not exist ✅[^lab] | Registration copies no methods; a registered class should define the full API (application programming interface) itself ✅[^collections-abc] |
| ABC subclass that omits one abstract method | The class statement succeeds; `Half()` raises `TypeError` ✅[^lab] | Enforcement happens at instantiation ✅[^abc] |

## Trade-offs
| Option | Gains | Costs |
|---|---|---|
| `@dataclass` | Generated methods, per-field options, mutable by default ✅[^dataclasses] | Unhashable by default when mutable ✅[^dataclasses] |
| `@dataclass(frozen=True)` | Hashable, safe as a dict key or set member ✅[^dataclasses] | Small `__init__` overhead; changes go through `replace()` ✅[^dataclasses] |
| `typing.NamedTuple` | Immutable, indexable, unpackable, no per-instance dictionary ✅[^collections] | Equal to a plain tuple with the same values: `Emp("Guido") == ("Guido", 3)` is `True` ✅[^lab]; no `super()` in methods ✅[^typing] |
| Plain `Enum` | Members never equal raw values, so mix-ups fail loudly ✅[^howto-enum] | Use `.value` at system boundaries |
| `IntEnum` / `StrEnum` | Drop-in replacement for existing integer or string constants ✅[^enum] | Members of two different `IntEnum` classes can compare equal ✅[^howto-enum] |
| Inheriting from an ABC | Missing methods caught at instantiation; mixin methods ✅[^abc] | Requires inheritance; multiple inheritance can cause metaclass conflicts ✅[^abc] |
| `ABC.register()` | Works for classes you do not own ✅[^abc] | Nothing enforced, no mixins ✅[^abc] |

## Takeaways
- Give every mutable dataclass default a `field(default_factory=...)`. [rule-candidate]
- Use `@dataclass(frozen=True)` for value objects that serve as dict keys or set members, and change them with `replace()`. [rule-candidate]
- Remember that `replace()` and `copy.replace()` are shallow: mutable field values are shared with the original.
- Convert external input to enum members with `Cls(value)` at the boundary and handle the `ValueError`.
- Prefer plain `Enum`; reach for `IntEnum` or `StrEnum` only when members must pass as integers or strings.
- Place `@abstractmethod` innermost when stacking it with `@property`, `@classmethod` or `@staticmethod`. [rule-candidate]
- Inherit from a `collections.abc` base to get mixin methods; `register()` only labels a class.
