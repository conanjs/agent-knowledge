# Serde: data model, derive attributes and zero-copy deserialization

## Summary
**TL;DR:** Serde splits serialization in two halves that meet in a fixed vocabulary of 29 types, the serde data model. A type's `Serialize`/`Deserialize` impl (usually derived) describes the value in that vocabulary; a format crate such as `serde_json` turns the vocabulary into bytes and back. `#[serde(…)]` attributes change the description: names, defaults, skipped and flattened fields, and one of four enum representations. A `&'a str` field borrows straight from the input text, which fails when the JSON string contains an escape; `Cow<'a, str>` with `#[serde(borrow)]` borrows when it can and copies when it must.
**Use this when:** shaping JSON or config types, choosing an enum representation, reading errors such as "unknown field", "expected a borrowed string" or "data did not match any variant of untagged enum", or deciding between typed structs and `serde_json::Value`.
**Not this doc:** how a derive macro works inside → `rust/macros/procedural-macros.md`; `Cow<str>` itself → `rust/collections/strings-and-utf-8.md`; lifetime annotations → `rust/ownership/lifetimes.md`; higher-ranked bounds such as `for<'de>` → `rust/traits-and-generics/advanced-traits-and-type-system.md`; serde in `no_std` builds → `rust/ecosystem/no-std-embedded-and-webassembly.md`.

## Problem
External JSON uses `camelCase` keys and optional fields; a typo in a config key is silently ignored; an enum can be written as JSON in at least four conventions, and the default may not be the one an API expects; untagged enums report only "did not match any variant"; deserializing into `String` fields allocates a copy of every string, which borrowed fields avoid ✅[^9]. Each of these is decided by a few attributes and by which side of the data model does what.

## Mental model
**Analogy:** a pivot language at a translation office. Every data structure learns to speak the pivot language, and every file format learns to translate from it, so N types and M formats need N + M translators instead of N × M. The pivot language has a small, fixed vocabulary: "a struct named X with 2 fields", "a field named y", "a string", "an f32".

**Artifact:** what `#[derive(Serialize)]` generated for a two-field struct, from `cargo +nightly rustc -- -Zunpretty=expanded` ✅[^1]:
```rust
#[derive(Serialize)]
struct Reading { sensor: &'static str, celsius: f32 }
// generated (trimmed):
let mut __serde_state = _serde::Serializer::serialize_struct(__serializer, "Reading", false as usize + 1 + 1)?;
_serde::ser::SerializeStruct::serialize_field(&mut __serde_state, "sensor", &self.sensor)?;
_serde::ser::SerializeStruct::serialize_field(&mut __serde_state, "celsius", &self.celsius)?;
_serde::ser::SerializeStruct::end(__serde_state)
// serde_json::to_string(&Reading { sensor: "t1", celsius: 21.5 }) → {"sensor":"t1","celsius":21.5}
```
The impl never mentions JSON: it speaks only data-model calls, and `serde_json` decides that a struct becomes an object ✅[^1] ✅[^3].

## How it works
Three actors:
- **The type's impl** — its job: describe a value in data-model terms, via the `Serialize`/`Deserialize` traits, usually generated by `#[derive]`.
- **The format** — its job: map data-model terms to bytes and back, via its `Serializer`/`Deserializer` implementations (`serde_json` here).
- **The visitor** — its job: build the Rust value from what the format found, via a `Visitor` type that the `Deserialize` derive generates.

```
serialize:   Reading ──Serialize::serialize──▶ serialize_struct / serialize_field / end ──serde_json──▶ {"sensor":"t1",…}
deserialize: {"sensor":"t1",…} ──serde_json sees `{`──▶ visitor.visit_map(entries)
                 ▲                                              │ match key → field, collect values
                 └── Reading::deserialize calls ─────────────────┘ deserialize_struct("Reading", FIELDS, visitor)
```

1. **The data model.** 29 types: 14 primitives (`bool`, `i8`–`i128`, `u8`–`u128`, `f32`, `f64`, `char`), string, byte array, option, unit, unit struct, unit variant, newtype struct, newtype variant, seq, tuple, tuple struct, tuple variant, map, struct and struct variant ✅[^3]. A type may map to it indirectly; `OsString` is described as an enum of Unix and Windows variants ✅[^3].
2. **Serialize.** The impl calls the format's methods in data-model terms (the artifact above), so Serde needs no run-time reflection ✅[^2] ✅[^3]. The derive generates the impl at compile time from `#[derive(Serialize, Deserialize)]`, enabled by serde's `derive` feature ✅[^4].
3. **Deserialize, step by step** (names from the expanded derive) ✅[^1]:
   - `Reading::deserialize` calls `deserializer.deserialize_struct("Reading", FIELDS, __Visitor)`, a hint of the expected shape.
   - `serde_json` reads the input and calls the visitor method matching what it found: `visit_map` for `{…}`, `visit_seq` for `[…]`. The derived visitor has both, so `["t1", 21.5]` also deserializes into `Reading` ✅[^1].
   - The visitor maps each key to an internal `__Field` enum; unknown keys become `__ignore`, which is why unknown fields are skipped by default ✅[^1] ✅[^5].
   - A field never seen ends in `missing_field("sensor")`, unless a default applies ✅[^1].
   - Anything else, such as a bare string, fails with the visitor's `expecting` text: `invalid type: string "t1", expected struct Reading` ✅[^1].
4. **Zero-copy borrowing.** `Deserialize<'de>` carries the lifetime `'de` of the input, so the output may borrow from it ✅[^9].
   - `&str` and `&[u8]` fields borrow automatically; other types, such as `Cow<'a, str>`, borrow only with `#[serde(borrow)]` ✅[^9].
   - Measured: in `{"kind":"login","note":"ok",…}` both `kind: &'a str` and `#[serde(borrow)] note: Cow<'a, str>` point into the input buffer, and a `Cow` field without the attribute is `Owned` ✅[^1].
   - With an escape (`"log\nin"`) the decoded text differs from the input bytes, so a `&str` cannot point at it: `invalid type: string "log\nin", expected a borrowed string at line 1 column 17`. The `#[serde(borrow)] Cow` field turns `Owned` for `"o\"k"` and succeeds ✅[^1].
   - `serde_json::from_reader` requires `DeserializeOwned` (`for<'de> Deserialize<'de>`), because the input is gone when it returns ✅[^9] ✅[^14]. With a borrowing struct the call fails to compile: ``error: implementation of `Deserialize` is not general enough`` ✅[^1].
5. **Enum representations**, with the JSON `serde_json` 1.0.154 wrote for `Ping`, `Move { x: 1, y: 2 }` and `Say("hi")` ✅[^1] ✅[^7]:

   | Representation | Attribute | `Ping` | `Move { x: 1, y: 2 }` | `Say("hi")` |
   |---|---|---|---|---|
   | External (default) | none | `"Ping"` | `{"Move":{"x":1,"y":2}}` | `{"Say":"hi"}` |
   | Internal | `#[serde(tag = "type")]` | `{"type":"Ping"}` | `{"type":"Move","x":1,"y":2}` | not representable (see Edge cases) |
   | Adjacent | `#[serde(tag = "t", content = "c")]` | `{"t":"Ping"}` | `{"t":"Move","c":{"x":1,"y":2}}` | `{"t":"Say","c":"hi"}` |
   | Untagged | `#[serde(untagged)]` | (not in the tested enum) | `{"x":1,"y":2}` | `"hi"` |

   Untagged deserialization tries the variants in declaration order and keeps the first that fits ✅[^7]: with variants `Move`, `Say(String)`, `Num(f64)`, the input `7` becomes `Num(7.0)` and `true` fails with `data did not match any variant of untagged enum Untagged` ✅[^1].
6. **`serde_json::Value`.** An untyped tree with six variants: `Null`, `Bool`, `Number`, `String`, `Array`, `Object` ✅[^12]. `v["user"]["missing"]` yields `Null` rather than panicking, `get` returns an `Option`, and `as_str()` on a number is `None` ✅[^12] ✅[^1]. `json!` builds a `Value` from JSON-like syntax with Rust expressions inside ✅[^11]; `serde_json::from_value` turns a `Value` into a typed struct ✅[^1].

## Worked example
One config type using the common field and container attributes:
```rust
fn default_retries() -> u8 { 3 }

#[derive(Debug, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
struct JobSpec {
    job_name: String,
    #[serde(default = "default_retries")] max_retries: u8,
    #[serde(default)] tags: Vec<String>,
    #[serde(skip_serializing_if = "Option::is_none")] owner_email: Option<String>,
    #[serde(rename = "TTL")] ttl_secs: u32,
    #[serde(skip)] cache_hits: u64,
    #[serde(flatten)] extra: BTreeMap<String, serde_json::Value>,
}
```
Input `{"jobName":"nightly-backup","TTL":600,"region":"eu-1","priority":7}` gave, in the lab ✅[^1]:

| Stage | Real output |
|---|---|
| Deserialized | `JobSpec { job_name: "nightly-backup", max_retries: 3, tags: [], owner_email: None, ttl_secs: 600, cache_hits: 0, extra: {"priority": Number(7), "region": String("eu-1")} }` |
| Serialized back | `{"jobName":"nightly-backup","maxRetries":3,"tags":[],"TTL":600,"priority":7,"region":"eu-1"}` |
| With `owner_email: Some(…)` and empty `extra` | `{"jobName":"nightly-backup","maxRetries":3,"tags":[],"ownerEmail":"ops@example.org","TTL":600}` |

What each attribute did:
- `rename_all = "camelCase"` renamed every field; a field-level `rename` (`TTL`) wins over it ✅[^1] ✅[^5] ✅[^6].
- `default = "default_retries"` filled the missing `maxRetries` with 3 and `default` filled `tags` from `Default` ✅[^1] ✅[^6].
- `skip_serializing_if` left `ownerEmail` out while it was `None` ✅[^1] ✅[^6].
- `skip` kept `cache_hits` out of both directions, so its type must implement `Default` (or name a `default` function) ✅[^1] ✅[^6].
- `flatten` on a map collected the keys no other field claimed and wrote them back inline ✅[^1] ✅[^8].

## Edge cases
| Case | What happens | Why |
|---|---|---|
| Typo key `mem_gb` with `#[serde(deny_unknown_fields)]` | ``unknown field `mem_gb`, expected `cpu` or `mem_mb` at line 1 column 30`` | The attribute turns `__ignore` into an error ✅[^1] ✅[^5] |
| Same input without the attribute | Accepted, typo silently dropped | Self-describing formats ignore unknown fields by default ✅[^1] ✅[^5] |
| `deny_unknown_fields` plus `flatten` | Serde documents the pair as unsupported; in this version an extra key was still rejected, as ``unknown field `sort` `` without the expected list | Do not rely on the combination ✅[^5] ✅[^8] ✅[^1] |
| Missing required field | ``missing field `mem_mb` at line 1 column 9`` | No `default` on the field ✅[^1] |
| Wrong type | `invalid type: string "two", expected u32` | The visitor's `expecting` text ✅[^1] |
| Internally tagged enum with `Say(String)` | Compiles; serializing fails at run time: `cannot serialize tagged newtype variant Bad::Say containing a string` | A tag can sit only beside struct or map content; tuple variants are a compile error ✅[^1] ✅[^7] |
| Unknown variant, internal tag | ``unknown variant `Jump`, expected `Ping` or `Move` `` | Tag value matched against variant names ✅[^1] |
| Untagged enum, no variant fits | `data did not match any variant of untagged enum …`, no detail | Each variant is tried in order; the container `expecting` attribute can improve the message ✅[^1] ✅[^5] |
| Map with tuple keys | `to_string` fails: `key must be a string` | JSON object keys are strings ✅[^1] ✅[^15] |
| Map with `u32` keys | `{"7":"seven"}` | Integer keys are written as strings ✅[^1] |
| `f64::NAN`, `f64::INFINITY` | Serialized as `null`; reading it back as `f64` fails: `invalid type: null, expected f64` | `serde_json` writes non-finite floats as `null` ✅[^1] |
| `json!({"port": …, "tls": …, "hosts": …})` | Printed as `{"hosts":[…],"port":8080,"tls":false}` | Maps are kept sorted unless the `preserve_order` feature is on ✅[^1] ✅[^13] |
| `from_reader` on a `File` | Slower than reading into memory and `from_slice`; unbuffered | Wrap in `BufReader` or read first ✅[^14] |
| Internally tagged, adjacently tagged and untagged in `no_std` without `alloc` | Unavailable | Deserializing them buffers content; only external tagging works without an allocator ✅[^7] ✅[^10] |

## Trade-offs
| Option | Gains | Costs |
|---|---|---|
| Typed structs with derive | Compile-time field checks and editor help ✅[^11] | One type per shape |
| `serde_json::Value` | Any shape, no type to write | Missing keys become `Null`; little compile-time help ✅[^11] |
| Borrowed `&'a str` fields | No allocation for unescaped strings | Fails on escapes; the value cannot outlive the input |
| `#[serde(borrow)] Cow<'a, str>` | Borrows when possible, copies on escapes | Callers must handle both cases |
| External tagging | Works with no allocator; every variant kind | Extra nesting level |
| Internal or adjacent tagging | Flat, API-friendly JSON | Needs `alloc`; internal tagging rejects tuple and some newtype variants |
| Untagged | Shortest JSON | Order-dependent; vague errors; needs `alloc` |

## Takeaways
- Put `#[serde(deny_unknown_fields)]` on config types read from files, so a misspelt key fails loudly. [rule-candidate]
- Use `skip_serializing_if = "Option::is_none"` on optional output fields instead of writing `null`.
- Choose the enum representation the external format expects; avoid `untagged` when error quality matters, and order its variants from most to least specific. [rule-candidate]
- Use `&'a str` only when inputs are known to be escape-free; otherwise use `#[serde(borrow)] Cow<'a, str>` or `String`.
- Accept `DeserializeOwned` in functions that read from an `io::Read`.
- Read the generated impl with `cargo +nightly rustc -- -Zunpretty=expanded` when an attribute does not behave as expected.
